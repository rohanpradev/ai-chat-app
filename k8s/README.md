# Kubernetes Runbook

This directory only stores generated local Kubernetes values. The supported source of truth is the Helm chart in `helm/chat-app/` plus the helper scripts in `scripts/`.

Generated local files:

- `helm/chat-app/values.local.yaml`
- `k8s/traefik-values.generated.yaml`

## Prerequisites

- A local Kubernetes runtime such as Docker Desktop, OrbStack, kind, or Minikube
- `kubectl`
- `helm`
- Docker, when building and loading local images
- A repo-root `.env` created from `.env.example`

The deployment checker uses Kubernetes `1.36.2` for template validation by default. The chart supports Kubernetes `1.33.x` through `1.36.x`, matching Helm 4.2's supported version skew. Override with a supported patch version such as `KUBE_VERSION=1.35.6` when validating an older target cluster.

## Validate

Run the deployment gate before changing chart, Docker, or proxy behavior:

```bash
bun run check:deploy
```

It validates:

- Docker Compose syntax with `docker compose config --quiet`
- Dockerfile build checks when the Docker daemon is reachable
- Strict Helm linting
- Helm template rendering with and without Gateway API CRDs
- Expected Kubernetes hardening markers: probes, NetworkPolicies, HPA, PDB, non-root security context, read-only root filesystems, disabled service account token mounts, and RuntimeDefault seccomp

If Docker is installed but the daemon is stopped, Dockerfile build checks are skipped. Set `DEPLOY_CHECK_REQUIRE_DOCKER=1` to make that a failure.
Set `DEPLOY_CHECK_USE_VALUES_TEMPLATE=1` to validate the checked-in local template without reading or generating values from `.env`.

## Local NodePort Mode

This is the simplest local Kubernetes path:

```bash
K8S_GATEWAY_ENABLED=false
make kubernetes
```

Expected local URLs:

- Client: `http://localhost:30080`
- API health: `http://localhost:30001/health`

## Local Gateway Mode

Gateway mode installs Traefik and routes through hostname-based HTTPS:

```bash
K8S_GATEWAY_ENABLED=true
K8S_APP_HOSTNAME=app.docker.localhost
make kubernetes
```

Gateway listeners accept routes only from `K8S_APP_NAMESPACE` (default `default`). `make K8S_NAMESPACE=<namespace> kubernetes` propagates the selected application namespace into the Traefik listener selector.

Expected local URLs:

- App: `https://app.docker.localhost:30001`
- API health through the app route: `https://app.docker.localhost:30001/api/health`
- Traefik dashboard: `https://traefik.docker.localhost:30001`

The app chart only emits Gateway API resources when the cluster reports `gateway.networking.k8s.io/v1`. This keeps the same chart renderable in clusters that do not have Gateway API CRDs installed.

## Images

Local values generated by `scripts/ensure-k8s-secrets.sh` use:

- `chat-app-client:latest`, `chat-app-server:latest`, and `chat-app-migrate:latest` with `pullPolicy: Never`
- Public `pgvector/pgvector:0.8.5-pg18-trixie` and `redis:8.8.1-trixie` images for local stateful services

Production values use Bun `1.3.14`, Nginx `1.31.3`, Redis `8.8.1`, and pgvector `0.8.5` on PostgreSQL 18. The local Gateway workflow pins Traefik chart `41.1.0`; both the upstream Compose image and DHI override use Traefik `3.7.9`. Every image can be overridden by registry, repository, tag, or digest; prefer immutable digests for production releases.

Traefik 3.7's current Kubernetes Gateway provider documentation declares support for Gateway API `1.6.1`, so the installer pins `GATEWAY_API_VERSION=v1.6.1` and applies that release's standard CRDs before installing Traefik. The installer uses server-side apply, refuses to replace experimental or unrecognized bundles, blocks Gateway API downgrades, and requires minor releases to be upgraded one at a time. Because Gateway API CRDs are cluster-scoped, production clusters should keep their ownership with the cluster provisioning layer and verify the signed Traefik chart release before rollout.

Gateway API CRDs are deliberately not rolled back with the Traefik release. To roll back Traefik, select the previous chart and image versions while leaving the compatible Gateway API CRDs in place; restore cluster CRDs only from a reviewed cluster backup if a release-specific incident requires it.

The migration job enables the `vector` extension before converting or indexing embeddings. External PostgreSQL services must provide pgvector and permit the migration role to run `CREATE EXTENSION IF NOT EXISTS vector`; otherwise install the extension through the database platform before upgrading the app. Helm runs migrations after a first install and before an upgrade, so an existing release is migrated before new server pods roll out. Local setup keeps the explicit `make k8s-migrate` step after the database StatefulSet is available.

Before rolling the database or Redis image, take recoverable backups. PostgreSQL remains on major version 18, so this change does not require `pg_upgrade`, but replacing the image does not update an extension already installed in an existing database. After the new database image is healthy, check `SELECT extversion FROM pg_extension WHERE extname = 'vector';` and, when needed, run `ALTER EXTENSION vector UPDATE;` as a privileged database operator. After that update, rollback must use an image that provides at least the installed pgvector version or restore the pre-upgrade backup.

## Operations

```bash
make k8s-setup      # generate values.local.yaml from .env
make k8s-build      # build local app images
make k8s-deploy     # helm upgrade --install
make k8s-migrate    # run migration Job explicitly
make k8s-test       # rollout checks plus HTTP smoke test
make k8s-status     # workloads, services, HPA, PDB, PVCs, routes, policies
make k8s-logs       # recent logs from all app pods
make k8s-cleanup    # remove app and Traefik resources, keep runtime running
make clean          # complete local teardown, including Docker and runtime
```

## Chart Posture

The chart renders:

- Client and server Deployments
- PostgreSQL and Redis StatefulSets for local or self-contained deployments
- A migration Job
- Services for each component
- NetworkPolicies with default-deny plus explicit DNS, client, server, DB, Redis, migration, and test rules
- Startup, readiness, and liveness probes
- HPA and PDB for client and server
- Optional Gateway API HTTPRoutes and Traefik Middleware CRDs

Pods disable service account token automounting and Kubernetes service-link env injection. App containers run as non-root, drop Linux capabilities, disallow privilege escalation, use RuntimeDefault seccomp, and mount writable paths with bounded `emptyDir` or PVCs.

## Troubleshooting

- `ImagePullBackOff` on app pods: run `make k8s-build`; local app images use `pullPolicy: Never`.
- `ImagePullBackOff` on Postgres or Redis: regenerate local values with `make k8s-setup`; local values should use public images unless you intentionally changed them.
- Gateway routes missing: install Gateway API CRDs and Traefik, or use `K8S_GATEWAY_ENABLED=false`.
- Smoke test fails in Gateway mode: confirm the hostname resolves to the local cluster and check `make k8s-status`.
- Migration Job fails: run `kubectl logs job/chat-app-migration -n default --tail=200`.
